- Profile text edits had only owner predicates, and certificate save used an unconditional id upsert. Marine edits/deletes and forum post/comment edits/deletes lacked original-content/revision predicates. Local APIs now reject changed/deleted baselines in the same mutation rather than pre-read-then-unconditional-write. Current-client protection does not retroactively stop old clients.
- Profile editors pin original text fields across cache/avatar refresh. Text updates use null-aware original-field comparisons and touch text fields only; avatar replacement compares its original avatar path and does not overwrite text. Conflict preserves copyable text, gives persistent guidance, blocks save and requires a confirmed latest-profile reload. Photo upload leftovers are not auto-deleted.
- Certificate draft pins original updated_at; new requests are insert-only with exact-content stable-id retry confirmation. Existing edits require owner, original revision and non-archived state. Archive and undo each require their exact revision; a stale editor cannot recreate an absent row or unarchive a removed certificate. Conflict retains draft/selected photo. Manual list reload does not adopt a new draft baseline. Draft remains visible during list-read failure.
- Marine record objects already pin editor state. Update/delete now atomically compare owner and all original editable fields plus created_at. Zero-row identical-content retry can acknowledge without another write; changed/missing content conflicts. A stale delete cannot delete the row or remove its photo. Conflict retains draft/photo and blocks save; users can copy, close, reload the list and reopen the latest record.
- Forum post/comment reads now include updated_at; editor and delete-confirmation state pin it rather than borrowing a background refresh. Mutations require owner/original revision and reject zero-row stale edits/deletes; identical update retries acknowledge without rewriting. Post errors remain in the composer. A remotely deleted/unavailable comment retains its editable text in a separate copyable read-only draft view instead of disappearing with the list row.

Profiles and marine records have no existing updated_at trigger in their source schema, so this batch compares relevant original field values without a migration. This is value-based compare-and-set, not a monotonic revision counter or a guarantee that every intervening equal-value/ABA change is detected. Certificate/forum timestamps follow their existing schema triggers, which must be checked on recovery before live acceptance.
